# weekly-closure

> Weekly project closure — run every Friday before 17:00. Reads all project status files, computes velocity, writes a per-project summary report, updates the todo list, and sends the summary by email to the team.

Version 1.0 · The agent adopts this persona throughout: Project manager performing the weekly team reporting cycle. · Spec reference: https://github.com/jtplugin/sol

## What it does

- Read all status.md files in projects/ [fast model]
- Run exactly: `python3 scripts/compute_velocity.py projects/`
  - If that fails:
    - Report that velocity computation failed and identify the cause
    - Stop the entire run — Cannot write the summary without velocity data — fix scripts/compute_velocity.py and re-run.
- Read reports/velocity.json [fast model]
- For each project in the projects/ directory:
  - Write the section for {{project}} in reports/weekly-summary.md: overall status (green / yellow / red), the three most relevant points of the week, and priorities for next week [from context: project] [smart model]
  - If {{project}} has velocity below 0.3 or has critical tasks blocked for more than 5 days, then: [from context: project]
    - Append an explicit alert note to {{project}}'s section in reports/weekly-summary.md [from context: project]
- In todo.md, move all tasks that appear as closed in the status files to the Completati section [fast model]
- In todo.md, add the priorities identified in the summary to the top of the Questa settimana section [fast model]
- Prepare the email body from the content of reports/weekly-summary.md [fast model]
- If at least one project has red status, then:
  - Prepend a bold alert line to the email body listing the names of all red-status projects
- Send an email to team@company.com with subject 'Weekly Summary — {{today}}' and body equal to the prepared email body [from context: today]
  - If that fails:
    - Save the prepared email body to reports/weekly-email-draft.md and report that the email could not be sent
